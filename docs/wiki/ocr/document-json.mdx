## Επισκόπηση

Κάθε έγγραφο που περνάει από αναγνώριση καταλήγει σε **ένα** δομημένο JSON — το «κανονικό JSON εγγράφου». Δεν είναι πλέον μια πλακέ λίστα κλειδιών (`companyName`, `totalAmount`, …) αλλά ένα αντικείμενο με **ενότητες**: ποιος εκδίδει, σε ποιον, τι γραμμές έχει, τι σύνολα, τι ψηφιακή σήμανση. Το ίδιο JSON χρησιμοποιείται παντού: το γεμίζει η αναγνώριση, το διορθώνουν τα πρότυπα, το κατεβάζεις σε Excel και από αυτό χτίζεται το παραστατικό που καταχωρίζεται στο SoftOne. Μία πηγή αλήθειας, όχι τρεις που διαφωνούν.

## Οι ενότητες του JSON

| Ενότητα | Τι κρατάει |
|---|---|
| `kind` | `invoice` (υπάρχει μπλοκ παραλήπτη), `receipt` (δεν υπάρχει) ή `general` (ελεύθερο κείμενο). |
| `type` | `label` (ο τυπωμένος τύπος αυτούσιος), `series`, `number`, `myDataType`. Το «ΤΠΥ 17» σπάει σε σειρά «ΤΠΥ» και αριθμό «17». |
| `date`, `dueDate`, `currency` | Ημερομηνία έκδοσης και λήξης σε `YYYY-MM-DD`, νόμισμα (προεπιλογή `EUR`). |
| `issuer` | Ο **εκδότης**: `name`, `vat`, `doy`, `profession`, `address`, `city`, `zip`, `country`, `phone`, `email`, `gemi`, `code`. |
| `recipient` | Ο **παραλήπτης** (η δική μας εταιρία) με τα ίδια πεδία. |
| `lines` | Οι γραμμές: `code`, `name`, `unit`, `quantity`, `unitPrice`, `discount`, `net`, `vatRate`, `vatAmount`, `total` και `custom` για ό,τι στήλη δεν χωράει αλλού. |
| `totals` | `net`, `discount`, `vatAmount`, `withholding` (παρακράτηση), `fees` (επιβαρύνσεις/τέλη), `total`, `payable` (πληρωτέο). |
| `vatBreakdown` | Ανάλυση ΦΠΑ ανά συντελεστή: `rate`, `net`, `vat`. |
| `digital` | Ψηφιακή σήμανση: `mark` (ΜΑΡΚ ΑΑΔΕ), `uid`, `authCode`, `provider`, `qr`. |
| `payment` | `method`, `terms` και `ibans` (λίστα `{bank, iban}`). |
| `references` | `orderNo`, `deliveryNote`, `contract`, `shipment`, `plates`, `period` (από/έως) και `quantities` (π.χ. κατανάλωση kWh). |
| `notes` | Ελεύθερες σημειώσεις του παραστατικού. |
| `handwritten` | Ό,τι είναι **χειρόγραφο** πάνω στο έντυπο: `glAccount` (λογιστικό άρθρο), `reference`, `allocations`. |
| `custom` | Οτιδήποτε δεν έχει θέση στο τυπικό σχήμα — εκεί καταλήγουν και τα έξτρα πεδία των προτύπων. |

## Η κάρτα «JSON εγγράφου»

<Steps>
  <li><strong>Πού είναι</strong> — στη σελίδα του εγγράφου (<code>/admin/ocr/[id]</code>), κάτω από την κάρτα «Πρότυπο». Εμφανίζεται μόνο σε <strong>ολοκληρωμένα</strong> έγγραφα.</li>
  <li><strong>Σύνοψη</strong> — μια σειρά από chips: είδος, τύπος, σειρά + αριθμός, ημερομηνία, εκδότης, ΑΦΜ, σύνολο με νόμισμα, ΜΑΡΚ (ή «χωρίς») και πλήθος γραμμών.</li>
  <li><strong>Πλήρες JSON</strong> — το πτυσσόμενο «Πλήρες JSON (v3)» δείχνει ολόκληρο τον φάκελο μορφοποιημένο.</li>
  <li><strong>«Αντιγραφή»</strong> — βάζει το JSON στο πρόχειρο.</li>
  <li><strong>«Λήψη»</strong> — κατεβάζει αρχείο <code>&lt;όνομα αρχείου&gt;.json</code> από το <code>GET /api/admin/ocr/[id]/document?download=1</code>.</li>
</Steps>

Ο **φάκελος** που κατεβαίνει έχει σταθερή μορφή:

```json
{
  "template": "kapaline",          // slug της τελευταίας μη-αποτυχημένης εκτέλεσης, ή null
  "version": 3,                    // έκδοση του ΣΧΗΜΑΤΟΣ (όχι του προτύπου)
  "extractedAt": "2026-09-12T08:15:00.000Z",
  "file": "TIM-1042.pdf",
  "documentId": "cmtv73bzp0000std41ex2c627",
  "document": { "kind": "invoice", "type": { }, "issuer": { } }
}
```

Το ίδιο σχήμα αποθηκεύεται και σε κάθε εκτέλεση προτύπου, οπότε το «JSON» της κάρτας «Πρότυπο» και το «JSON εγγράφου» μιλούν πλέον την ίδια γλώσσα.

## Πώς το γεμίζουν τα πρότυπα

Οι αντιστοιχίσεις ενός προτύπου δεν δείχνουν πια σε κλειδιά τιμολογίου αλλά σε **διαδρομές** του εγγράφου — `totals.payable`, `issuer.vat`, `lines.net`, `digital.mark`. Στο βήμα «Mapping» οι διαδρομές είναι ομαδοποιημένες (Τύπος & ημερομηνία, Εκδότης, Παραλήπτης, Σύνολα, Γραμμές, Ψηφιακή σήμανση, Πληρωμή, Αναφορές, Χειρόγραφα & σημειώσεις).

<Steps>
  <li>Ένα πεδίο που δείχνει σε <strong>διαδρομή κεφαλίδας</strong> γράφει εκεί την τιμή του — <strong>εκτός αν είναι κενή</strong>: ένα άδειο crop δεν σβήνει ό,τι διάβασε σωστά η κανονική αναγνώριση.</li>
  <li>Ένα πεδίο-<strong>πίνακας</strong> με στήλες σε <code>lines.*</code> ξαναχτίζει τις γραμμές του εγγράφου· όποια στήλη δεν αντιστοιχίστηκε κρατιέται στο <code>custom</code> της γραμμής.</li>
  <li>Κάθε <strong>απλό πεδίο του προτύπου που δεν εμφανίζεται σε καμία αντιστοίχιση</strong> πηγαίνει αυτόματα στο <code>custom.&lt;κλειδί πεδίου&gt;</code>. Διαδρομή ή <code>custom</code>: τίποτα από όσα διάβασε το πρότυπο δεν χάνεται.</li>
</Steps>

<Callout type="info">
  Παλιά αποθηκευμένα mappings δουλεύουν αυτούσια: τα κλειδιά τους (<code>totalAmount</code>, <code>items.price</code>, <code>customFields.x</code>) μεταφράζονται αυτόματα στις αντίστοιχες διαδρομές (<code>totals.total</code>, <code>lines.unitPrice</code>, <code>custom.x</code>) και εμφανίζονται πλέον με το κανονικό τους όνομα.
</Callout>

## Πού καταλήγει

- **Excel** — το αρχείο έχει τώρα **τρία φύλλα** ανά πρότυπο: το κύριο (μία γραμμή ανά έγγραφο, με στήλες Τύπος, Σειρά, Αριθμός, Ημερομηνία, Εκδότης, ΑΦΜ εκδότη, Παραλήπτης, Καθαρή αξία, Έκπτωση, ΦΠΑ, Παρακράτηση, Επιβαρύνσεις, Σύνολο, Πληρωτέο, ΜΑΡΚ και μετά τις στήλες του προτύπου), το **«… — Γραμμές»** από το `lines[]` και το **«… — ΦΠΑ»** από το `vatBreakdown`. Τα ποσά μένουν αριθμοί, όχι κείμενο.
- **SoftOne** — το payload καταχώρισης (`PURDOC`) χτίζεται **αποκλειστικά** από το κανονικό JSON και τις αντιστοιχίσεις των γραμμών: κεφαλίδα από `type.number`, `date`, `digital.mark`/`digital.uid`, γραμμές σε `ITELINES` (είδη), `SRVLINES` (υπηρεσίες) και `EXPANAL` (έξοδα).
- **Λίστα & καρτέλα** — τα γνωστά πεδία (ΑΦΜ, αριθμός, σύνολα, γραμμές) εξακολουθούν να φαίνονται όπως πριν· απλώς **παράγονται** πλέον από το κανονικό JSON αντί να αποθηκεύονται ξεχωριστά.

## Καταχώριση στο SoftOne — προεπισκόπηση

Μέσα στην ίδια κάρτα, όποιος έχει δικαίωμα ανάρτησης βλέπει την ενότητα **«Καταχώριση στο SoftOne»**. Φορτώνει πάντα σε κατάσταση **dry-run**: δείχνει τι *θα* σταλεί, χωρίς να στείλει τίποτα.

<Steps>
  <li><strong>Εκκρεμότητες</strong> — αν κάτι εμποδίζει την καταχώριση, εμφανίζεται πορτοκαλί λίστα «Εκκρεμότητες πριν την καταχώριση» με έναν λόγο ανά γραμμή. Αλλιώς: «Το παραστατικό είναι έτοιμο για καταχώριση».</li>
  <li><strong>Κεφαλίδα</strong> — Σειρά, Προμηθευτής (με τον κωδικό TRDR), Ημερομηνία, Αριθμός.</li>
  <li><strong>Γραμμές</strong> — πίνακας με Γραμμή, Τύπος (Είδος / Υπηρεσία / Έξοδο), Κωδικός SoftOne, Περιγραφή, Ποσότητα, Τιμή / Αξία, ΦΠΑ.</li>
  <li><strong>«Προβολή payload»</strong> — το ακριβές JSON που θα σταλεί στο SoftOne.</li>
  <li><strong>«Καταχώριση»</strong> — ενεργό μόνο όταν δεν υπάρχει καμία εκκρεμότητα <em>και</em> η καταχώριση είναι ενεργοποιημένη στις Ρυθμίσεις.</li>
</Steps>

### Οι εκκρεμότητες και τι σημαίνουν

| Μήνυμα | Τι λείπει |
|---|---|
| Το έγγραφο δεν έχει ολοκληρωθεί | Η αναγνώριση δεν τελείωσε (κατάσταση ≠ COMPLETED). |
| Δεν έχει οριστεί κατηγορία εγγράφου | Λείπει η κατηγορία του εγγράφου. |
| Δεν έχει αντιστοιχιστεί προμηθευτής στο SoftOne | Ο εκδότης δεν έχει `TRDR` — δες [Νέοι συναλλασσόμενοι](/wiki/ocr/new-traders). |
| Δεν έχει επιλεγεί σειρά παραστατικού | Λείπει η σειρά ή η πηγή της — δες [Αναγνώριση τύπου παραστατικού](/wiki/ocr/doc-type). |
| Λείπει η ημερομηνία του παραστατικού | Κενό `date`. |
| Λείπει ο αριθμός του παραστατικού | Κενό `type.number`. |
| Το έγγραφο δεν έχει γραμμές | Κενό `lines[]`. |
| Υπάρχουν γραμμές χωρίς αντιστοίχιση σε είδος ή έξοδο | Κάποια γραμμή δεν έχει `MTRL` ούτε `EXPN` — δες [Είδη & έξοδα](/wiki/ocr/new-items). |
| Συντελεστής ΦΠΑ γραμμής χωρίς κωδικό στο μητρώο ΦΠΑ | Ο συντελεστής μιας γραμμής δεν αντιστοιχεί σε κωδικό ΦΠΑ του SoftOne. |
| Το άθροισμα των γραμμών δεν συμφωνεί με την καθαρή αξία | Το σύνολο των `lines.net` απέχει πάνω από 0,05 € από το `totals.net`. |
| Η καταχώριση είναι απενεργοποιημένη (Ρυθμίσεις → Διασυνδέσεις) | Ο διακόπτης ασφαλείας είναι κλειστός. |

<Callout type="warning">
  Η καταχώριση παραστατικών στο SoftOne είναι <strong>κλειστή από προεπιλογή</strong>. Ο διακόπτης βρίσκεται στις <strong>Ρυθμίσεις → Διασυνδέσεις → «Καταχώριση παραστατικών στο SoftOne»</strong>. Όσο είναι κλειστός: η κάρτα δείχνει <strong>μόνο προεπισκόπηση</strong>, το κουμπί «Καταχώριση» είναι ανενεργό, και κάθε <strong>αυτόματο (AUTO)</strong> πρότυπο που θα προσπαθούσε να αναρτήσει καταλήγει σε εκτέλεση <strong>«Μπλοκαρισμένο»</strong> με λόγο «Η καταχώριση είναι απενεργοποιημένη». Καμία εγγραφή δεν φεύγει προς την ERP.
</Callout>

<Callout type="info">
  Όταν η καταχώριση είναι ενεργοποιημένη, το σύστημα δεν αρκείται στο <code>success: true</code> του SoftOne: <strong>ξαναδιαβάζει</strong> το παραστατικό που δημιουργήθηκε και επαληθεύει αριθμό και προμηθευτή πριν σημάνει το έγγραφο «Αναρτήθηκε».
</Callout>

<Callout type="danger">
  Έγγραφα που σαρώθηκαν <strong>πριν</strong> από αυτή την αλλαγή έχουν συμπληρωμένο μόνο ό,τι κρατούσε η παλιά πλακέ μορφή (εκδότης, αριθμός, ημερομηνία, σύνολα, γραμμές). Οι νέες ενότητες — <code>vatBreakdown</code>, <code>references</code>, <code>handwritten</code>, <code>payment.terms</code>, <code>totals.withholding</code> — μένουν κενές. Για πλήρες JSON κάνε <strong>«Επανεκτέλεση OCR»</strong> στο έγγραφο.
</Callout>
